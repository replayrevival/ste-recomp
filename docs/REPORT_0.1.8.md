## 2. Controller in the in-game menu
- Finding (c419, ste_settings_glue.c pump_input): the overlay already reads SDL pads (ste_sdl_raw_buttons), but the SDL state is refreshed only by ste_sdl_update(), which the GAME's XInput poll calls (recomp_manual.c:252). While the overlay is open the game thread is held, so the raw state never changed: a real controller did nothing, keyboard and mouse (own sources) worked. Fix: pump_input calls ste_sdl_update() itself. Patch patches\c419_overlay_pad_poll.patch. c419 SHA 7C226903C69AE8FFA03495214EAF6EDD0E7D6D69C98F9721ACE7365D95D352C7 (built; verification with SDL's virtual joystick pending).
- Launcher side (launcher-21): STE_NAV_PREV_TAB/NEXT_TAB, STE_INPUT_NAV_RELEASE (overlay repeats held directions itself after the first release is seen), "[OVERLAY] page <name>" log. Told them LB = pad-script 'b', RB = 'w'; asked for a scratch dll on F:\GodzillaSTE_work\ov_dll_018\.
