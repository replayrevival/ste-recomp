# NOTE FOR THE LAUNCHER SESSION: photo mode (0.3.1)
Reference: docs\formats\photo_mode.md (controls, settings, how it works).
1. **Overlay entry.** Add a button "Photo mode" (hint: "Pause the match and fly a free camera; B or Esc closes it"). On press call `apply_setting("camera.open_photo_mode", "1")` and then close the overlay: the game opens the free camera at the next frame of a running fight. It works only inside a fight (Versus, Melee, Survival, Action, Solo Destruction ...); in menus the request is dropped (log line only). Disable the button when `[camera] photo_mode = off` (the game then ignores the request too).
2. **Capability name:** `photo_mode` (added to artifacts\capabilities.json; also `recipe_mods`, `solo_destruction_mod` from 0.3.0).
3. **ini keys** (ste_enhance.ini `[camera]`): `photo_mode = on|off` (default on, needs a restart), `photo_key = F8`, `photo_screenshot_key = F12`, `photo_hud_key = H` (key names F1..F24, a single letter/digit, `Tab`, `Space`, `Escape`, `none`), `photo_speed = 400` (units per second), `photo_range = 8000`, `photo_pad_chord = off|on` (Back + Y held 0.6 s opens it from the controller without the overlay).
4. **Controls text for the guide** is the table in docs\formats\photo_mode.md. Screenshots go to `<data>\screenshots\photo_<date>_<time>_<n>.png` (full resolution of the game window's swap chain, no overlay, PNG). Please show the folder in the Gallery/Screenshots tab if you have one.
5. **Honest limits to quote:** the simulation and the match clock are frozen while it is open; the HUD clock picture keeps counting while the HUD is visible and snaps back on close; the camera stays within `photo_range` units of where it was opened; not available in menus; live free camera while the match runs is NOT in this release.
